# Решения и допущения

- Одна компания; постановщики имеют общий доступ. У сотрудника одна роль, задачи назначаются исполнителям.
- Постановщик редактирует поля в любом статусе; автор и дата неизменны. Принятые задачи не открываются повторно.
- При переназначении доступ и история переходят новому исполнителю; прежний теряет доступ.
- Удаление скрывает записи, сохраняя историю. Удаление объекта скрывает его задачи. Архив доступен постановщику через API, без отдельного экрана.
- История содержит создание и смены статуса, без журнала правок полей. Комментарий до 4000 символов; для доработки обязателен.
- Сотрудники видят имена и роли коллег, но не их пароли и email.
- Устаревшие изменения отклоняются; обновление данных — кнопкой.
- Владелец базы имеет административные права; его ключ не входит в приложение.

## Ограничения

Обязательные функции реализованы. Не добавлены вложения, сроки, уведомления, управление сотрудниками, восстановление пароля и удалённых записей — они не требовались.

Данные загружаются порциями по 500; серверной фильтрации и страниц списка нет. Для больших объёмов нужна доработка. Нагрузочные испытания, одновременные транзакции, полный аудит доступности и все браузеры не проверялись.
